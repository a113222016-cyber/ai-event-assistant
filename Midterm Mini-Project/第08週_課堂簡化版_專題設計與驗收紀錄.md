# 專題設計與驗收紀錄

> 請將方括號內容替換成自己的實際資料。未做的測試請填「未測」，不可將範例當成真實測試。

## 一、專題定位

- 專題名稱：AI 活動報名訊息整理助手
- 目標使用者：需要閱讀社團、校園或公開活動公告的學生與一般參與者
- 使用情境：使用者收到一段活動公告，希望快速找到日期、地點、截止時間及下一步行動
- 核心任務：將活動公告整理成固定欄位，並標出原文未提供的資訊
- 選用技術：Streamlit、OpenAI Responses API、JSON Schema Structured Outputs
- 選用理由：欄位固定且需要逐欄呈現，JSON Schema 可明確限制欄位與型別

## 二、資料契約

| 欄位 | 型別 | 用途 |
|---|---|---|
| event_name | string | 活動名稱 |
| event_date | string | 活動日期與時間 |
| location | string | 活動地點 |
| registration_deadline | string | 報名截止時間 |
| target_audience | string | 參加對象 |
| key_details | array[string] | 重要資訊 |
| action_items | array[string] | 下一步行動 |
| missing_information | array[string] | 待確認資訊 |

所有欄位必填，禁止額外欄位。原文未提供的單一欄位填「未提及」。

## 三、測試紀錄

| 測試項目 | 預期結果 | 實際結果／證據 | API 請求數 |
|---|---|---|---:|
| 空白輸入 | 顯示提示，不呼叫 API | 未測 | 0 |
| 未同意 API | 顯示提示，不呼叫 API | 未測 | 0 |
| 超過 6,000 字元 | 阻止提交 | 未測 | 0 |
| 正常活動公告 | 產生結構化結果並逐欄核對 | 未測 | 1（規劃值） |
| 資訊不足公告 | 缺漏欄位標示未提及／待確認 | 未測 | 1（規劃值） |
| 缺少 API Key | 請求前停止並提示設定 | 未測 | 0 |
| 雲端部署 | 老師可開啟，且雲端真實 API 成功 | 未部署 | 未測 |
